# Music-unsynced/ — README for future agents

This folder lives alongside `Music/` (the **master** library). Anything here is
preserved as cloud backup but is **NOT** part of the canonical library and must
not be pulled to mirroring devices (Eversolo, etc.).

## What gets uploaded here

Items the user wants kept off the master to keep `Music/` clean:

1. **Eversolo-only anomalies** — albums on the Eversolo that have no equivalent
   on Drive `Music/`. They bypassed the rip→tag→upload workflow somehow and need
   review before being promoted to the master.
2. **"Eversolo wins" copies** — same album exists on `Music/` but Eversolo's
   copy is materially better:
   - more tracks (e.g. *Miles Davis — Kind of Blue* with bonus tracks)
   - tag-verified to be the *correct* recording when the master copy is
     mis-tagged (e.g. master folders that look like an album but whose tracks
     are tagged with a different artist)
3. **Variant editions** — different mixes / pressings the user wants archived
   (mono vs stereo, specific catalog numbers, etc.).

## Folder layout

Paths under `Music-unsynced/` mirror the **original Eversolo path** the file came
from. This makes the provenance obvious. We do **not** rename to match the
master's filing — the whole point is that this material isn't in the master.

## Conventions for the next sync agent

- **Sync direction is one-way: Drive `Music/` → Eversolo.** Never auto-sync
  from `Music-unsynced/` to a mirror.
- **Album matching is content-based** (normalized `artist | album`,
  format-agnostic). Different file formats (FLAC ⇄ ALAC ⇄ AIFF ⇄ WAV) for the
  same album are *not* a sync trigger.
- **Drive duplicates exist.** Some albums on `Music/` have multiple
  near-duplicate folders that differ only in case, punctuation, or curly vs
  straight quotes (see the `🧹 DUP-DRIVE` section in `~/sync-plan.md`). When
  pulling to Eversolo, emit only **one canonical path per album key** so the
  duplicates aren't propagated. Do not auto-dedupe — it's destructive and may
  lose intentional variants (e.g. `[Disc 1]` / `[Disc 2]` of a multi-disc set
  may collapse into one normalized key but represent legitimate distinct content).
- **The plan file is `~/sync-plan.md`.** Its trailing fenced block holds the
  machine-readable plan in `ACTION<TAB>side<TAB>path[<TAB>note]` format.
  Actions: `PULL`, `UPLOAD-UNSYNCED`, `REFACTOR`, `DUP-DRIVE`, `DUP-EVERSOLO`,
  `SKIP`. Regenerate with `eversolo-make-plan`; don't hand-edit it.
- **Sync script is `eversolo-sync`.** Default is dry-run; `--apply` to
  execute; `--only ACTION` to filter.
- **rclone config may be password-encrypted.** The password lives at
  `/tmp/rcpass` (mode 0600); rclone calls use `--password-command "cat /tmp/rcpass"`.
  If that file is missing, ask the user — don't try to bypass.

## Heads-up: things that might confuse you

- The Eversolo's USB drive shows up under volume UUID (e.g. `7DEF-F569`) over SMB.
  Path is `eversolo:Share/<UUID>/Music/`.
- `Compilations/` on Eversolo and `Various/` (or `Various Artists/`) on Drive
  hold the same kind of content; the matcher treats them as one bucket.
  Movie soundtracks live under the composer name on Eversolo and under
  `Soundtracks/` on Drive.
- Some `.aif` files fail tag-reading via mutagen — fall back to ffprobe.
